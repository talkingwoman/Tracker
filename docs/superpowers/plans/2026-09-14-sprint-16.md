# Sprint 16 Implementation Plan

**Goal:** Implement the mandatory Sprint 16 Tracker requirements: category selection/creation using MVVM with closure bindings and a two-page onboarding flow matching Figma. The starred whole-app MVVM migration is excluded.

## 1. Prepare the branch

- Fetch `origin` and verify that Sprint 15 is merged into `main`.
- Fast-forward local `main` and create `sprint_16` from it.
- Preserve the uncommitted design and plan documents; do not commit or push.

## 2. Add category MVVM tests first

- Add a unit-test target to the Xcode project.
- Add a fake category store and tests for loading, adding, selecting, and closure notifications.
- Run the tests and confirm the new tests fail before production implementation.

## 3. Implement category storage and MVVM

- Introduce a category store protocol that hides Core Data from the UI layer.
- Extend `TrackerCategoryStore` with category creation and fetched-results updates.
- Add `CategoryViewModel` with closure bindings and cell presentation data.
- Add the category list, custom cell, empty state, and new-category screen.
- Enforce the 38-character category name limit and correct button states.

## 4. Integrate categories into tracker creation

- Open category selection from the category row.
- Show the selected category as the row subtitle.
- Require title, category, emoji, color, and (for habits) schedule before enabling Create.
- Save the new tracker into the selected category instead of the hard-coded default category.

## 5. Add onboarding tests first

- Add tests for the persisted onboarding-completion state and page configuration.
- Confirm tests fail before implementation.

## 6. Implement onboarding from Figma

- Add the two exact Figma background images to the asset catalog.
- Build content view controllers for each page and a `.scroll` `UIPageViewController` container.
- Support swiping both directions, page-control updates, and the shared completion button.
- Persist completion in `UserDefaults` and dismiss onboarding permanently after the button is tapped.
- Route first launch through onboarding in `SceneDelegate`, otherwise show the tab bar.

## 7. Verify

- Run all unit tests and build the app for an iOS 17 simulator.
- Launch and manually verify first launch, swipe navigation, completion persistence, empty categories, category creation/selection, tracker creation, and persistence after relaunch.
- Compare onboarding and category screens against the referenced Figma frames and fix visible discrepancies.
- Review the final diff and confirm no starred task, commit, or push was performed.
